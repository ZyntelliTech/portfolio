Introduction

This is a low-cost, ultra-multifunctional STM32 smartwatch based on STM32F411CUE6, FreeRTOS, and LVGL.

System Diagram

The system block diagram is shown below. The main controller uses an STM32F411CEU6, the operating system uses FreeRTOS, and the graphics library uses LVGL. Sensors: Gesture recognition uses a 6-axis MPU6050; heart rate and blood oxygen sensors use an EM7028. There's very little information available about the EM7028(I collaborated with a Chinese supplier). I previously wrote a local peak-finding algorithm to calculate heart rate, but it wasn't very effective. So I've switched to using the official library. Altitude measurement uses an SPL06-001 barometer; the electronic compass uses an LSM303DLHC. In revision, the Bluetooth chip has been replaced with a KT6368A, which has SPP functionality and can be wirelessly updated.

Software Architecture

The software architecture of the watch is shown below.

The watch codes are divided into Bootloader and APP, in order to facilitate users to upgrade without disassembling the watch. A Flag area is divided after the BOOT area to record whether it is a complete APP. This location is recorded after the APP transfer is completed to ensure the integrity of the program.

  1. Low Power Design

The watch has three modes. The first is normal operation mode, in which the watch operates normally; the second is sleep mode, in which the MCU enters STOP mode but the MPU6050 continues to count steps and the third is shutdown mode, in which the TPS63020 is directly disabled. At this time, there is no 3V3 power supply, and only Vbat is powered.

Initially, I used the MPU6050's motion function to wake the watch from sleep mode, enabling interrupts and waking it up. However, this approach proved problematic because it required significant vibration to trigger the interrupt. So, we ultimately opted for the RTC timer interrupt, periodically detecting the current gesture state and waking it up if the wrist was raised.

If you use KT6328A for Bluetooth, it is not recommended to disable Bluetooth, as its standby power consumption is very low. However, the back panel of version 2.4 has been changed to completely disable Bluetooth, so you can directly use KT6368A and turn off Bluetooth when not in use.

Finally, I connected the 3V3 test, and the power consumption was 70-80mA in running mode, about 1mA in standby mode, and basically no power consumption in shutdown mode, with only the RTC working. Of course, I didn't test the power supply connected to the Vbat terminal through the DCDC power supply. The power consumption depends entirely on the efficiency of the DCDC.
